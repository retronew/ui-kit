## バナーの配列を自分で管理しない

Vue で「積み重なる toast」を作るときの反射的な発想は `ref<Banner[]>` です——
トリガーで push し、閉じるときに filter し、レンダリングで map する。この
サンプルはそのような配列を一切持ちません。`ErrorBannerCall.call(…)` の一回一回
が Root の Stack 内の独立したエントリであり、Root がそれらすべてを描画します。
エラーを 10 回発生させれば 10 個の Call があるだけで、Stack そのものがリスト
であり、それはあなたのコンポーネントではなくライブラリの中に存在します。

各 Call は Stack の独立したエントリであるため、それぞれが自分の `CallContext`
——つまり、この Call の Stack 内での位置を示す `call.index` を持ちます。これが
バナーの間隔を決めています。垂直方向のオフセットは単に `call.index * ROW_HEIGHT`
で、自前のカウンターを持たずに Callable の内部で読み取れます。これは
`call.index` が実際に仕事をする数少ない例の一つです。ほとんどの Callable は
これに触れることすらありません。

## 使いどころ

同時に存在するインスタンスが互いを置き換えるのではなく**共存すべき**場面では、
普通の `.call()` を使ってください——エラートースト、項目ごとの通知など、二つ目
のイベントが一つ目を上書きしてはいけない場面です。

一方で、その場で更新される**単一**の表示——プログレスバーや「保存中…→保存済み」
のピルが欲しいなら、それは堆積ではなく
[`upsert`](/ja/examples/progress-toast) の出番です。分かれ目はシンプルです。
新しい Call はバナーを追加すべきか、それとも既存のものを更新すべきか、という
問いです。
