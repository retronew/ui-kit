## 你不需要维护一个横幅列表

在 Vue 里做「堆叠 toast」的本能反应是用一个 `ref<Banner[]>`——触发时 push，
关闭时 filter，渲染时 map。这个示例完全没有这样的数组。每一次
`ErrorBannerCall.call(…)` 都是 Root 的 Stack 里一条独立的记录，Root 会把它们
全部渲染出来。触发十次错误就是十次调用；Stack **本身就是**那个列表，而且它
活在库里，不在你的组件里。

因为每个调用都是自己的 Stack 记录，它自带一份 `CallContext`——包括 `call.index`，
也就是这次调用在 Stack 里的位置。正是它决定了横幅之间的间距：垂直偏移量就是
`call.index * ROW_HEIGHT`，在 Callable 内部读取，完全不需要你自己维护计数器。
这是少数几个真正用到 `call.index` 的示例之一；大多数 Callable 从不碰它。

## 何时使用它

只要并发的实例应该**共存**而不是互相替换，就用普通的 `.call()`——错误提示、
按项目的通知，任何「第二个事件不应该覆盖第一个」的场景。

而当你想要的是一个**单一**、原地更新的界面——进度条、「保存中…→已保存」的
胶囊——那应该用 [`upsert`](/zh-cn/examples/progress-toast)，而不是堆叠。区分
标准很简单：一次新的调用应该新增一条横幅，还是更新已有的那条？
