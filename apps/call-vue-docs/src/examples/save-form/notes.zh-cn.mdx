## `useMutationFlow` 改变了什么

如果不用它，你得自己手动追踪 pending 状态和是否关闭的决定。这个 hook 负责
维护 **pending**——触发时为 true，处理函数结束时清空——所以你只需要用
`submit.pending` 去禁用输入，而不用自己维护一个布尔值。其余的一切仍然由你
决定：处理函数决定是否关闭（调用 `call.end(value)` 或者不调用）并自己处理
错误；这个 hook 从不接触抛出的异常。

勾选「**模拟保存失败**」再提交就能看到效果：处理函数跳过了 `call.end()`，
hook 清除了 pending，输入框保留原有内容，对话框保持打开以便重试。

## 何时使用它

- 提交按钮需要在请求进行中时禁用自己的场景。
- 「失败时保持打开」这种语义——用户不应该因为失败而丢失已经输入的内容。
- 处理函数是在**调用现场**提供的，而不是声明在 Callable 内部——这让两个不同
  的调用方可以对同一个表单运行不同的 mutation。

## 什么时候**不**该用它

如果对话框的目的只是读取一个值（颜色选择器、列表选择器），那么 mutation 应该
留在对话框外面。调用方直接写
`const id = await Picker.call(…); await api.delete(id)`——这样能让选择器保持
纯粹和可复用。
