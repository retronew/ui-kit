## なぜ `call` ではなく `upsert` なのか

`Toast.upsert(props)` を呼ぶたびに、単一のインスタンスを作成するか、その props
を更新します。返される promise はその単一インスタンスの生存期間を通じて
**同じ参照**です——`await Toast.upsert(…)` を一度書くだけで、その間にメッセージ
が何度変わろうと、トーストが最終的に閉じたときにコードが再開します。

`upsert` は単一のインスタンスを保つため、どこから呼び出された `Toast.upsert(…)`
も同じトーストを対象にします。二つ目の呼び出し元は新しいトーストを開くのでは
なく、既存のものを更新します。これはまさに進捗インジケーターが求める挙動です
——常に一つだけ存在すべきものです。各イベントが自分のトーストを持つべき場合は、
代わりに `.call()` を使えば Root がそれらを積み重ねてくれます（それが
[error-banner](/ja/examples/error-banner) の例です）。

## 使いどころ

- 作業の進行に合わせてメッセージが更新される進捗インジケーター。
- 「保存中…」から「保存済み」へ移り変わるステータスピル。
- セッション中に何度も切り替わる可能性のある接続状態バッジ。
