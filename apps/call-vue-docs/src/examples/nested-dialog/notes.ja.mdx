## 再帰は無料で手に入る

Callable コンポーネントは結局のところただの Vue コンポーネントです。その
テンプレートの中から、他の呼び出し元とまったく同じように `Callable.call(props)`
を呼び出せます——それによって同じ Callable の別のインスタンスが生成され、
それぞれが自分の props と自分の promise を持ちます。

ライブラリの Root は自身の Stack を走査し、開いている各 Call を描画します。
それらは並んで存在し、一つを閉じても他には影響しません。

## `call.index` と `call.stackSize` が与えてくれるもの

ヘッダーには「Level N · #i of M」と表示されます。

- `level` は呼び出し側が渡すただの prop です。各子が `level + 1` で開くため、
  ネストしても値が保たれます。
- `call.index` は CallContext から得られる、**この** Call の Stack 内での位置
  で、ゼロから始まります。
- `call.stackSize` は現在開いている総数で、兄弟の Call が開閉するたびにライブ
  に更新されます。

これらを使えば、中間のレンダリングに状態を通す必要なく、位置を意識した UI
（カスケードのオフセット、「Esc ですべて閉じる」、「1 / 3 件未保存」など）を
構築できます。

## すべてを一度に閉じる

promise を渡さない `Callable.end(response)` は開いているすべての Call へブロ
ードキャストされます。ここでは Response が `void` なので、`NestedDialogCall.end()`
はすべての階層を一度に終了させます——「Close all」ボタンはまさにこれを使って
います。CallContext からのターゲット指定の `call.end()` は、依然として自分が
属する Call だけを閉じます。

## DOM の仮想化

開いている Call はそれぞれ同じテンプレートをマウントするため、Stack が深く
なるほどコストがかさみます。このデモでは仮想化を行っています。

```ts
const visible = computed(() => call.index >= call.stackSize - DOM_LIMIT)
```

古いインスタンスは Stack に残ったままなので、一番上を閉じればそれらに戻れます
が、最上位 N 件に入るまではレンダリングをスキップします。`DOM_LIMIT = 10` の
場合、深さ 100 のネストでもレンダリングされるダイアログは 10 個だけです。
