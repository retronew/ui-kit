## 递归是免费的

Callable 组件说到底就是一个普通的 Vue 组件。在它自己的模板里，你可以像任何
其他消费者一样调用 `Callable.call(props)`——这会生成同一个 Callable 的另一个
实例，拥有自己的 props 和自己的 promise。

库内部的 Root 会遍历自己的 Stack，渲染每一个打开的调用。它们彼此并列存在；
关闭一个不会影响其他的。

## `call.index` 和 `call.stackSize` 能给你什么

标题读作「Level N · #i of M」：

- `level` 是调用方传入的普通 prop——它之所以能在嵌套中存活，是因为每个子级
  都用 `level + 1` 打开。
- `call.index` 来自 CallContext，是**当前**调用在 Stack 中的位置，从零开始。
- `call.stackSize` 是当前打开的总数，会随着兄弟调用的开关实时更新。

有了它们，你就能构建位置感知的界面（层叠偏移、「按 Esc 全部关闭」、「1 / 3 项
未保存」等），而不需要在每一层中间渲染时手动传递状态。

## 一次性全部关闭

不带 promise 的 `Callable.end(response)` 会广播给所有打开的调用。这里 Response
是 `void`，所以 `NestedDialogCall.end()` 一次性结束所有层级——「全部关闭」按钮
用的正是这个。CallContext 里定向的 `call.end()` 依然只关闭它自己所属的那一个。

## 虚拟化 DOM

每个打开的调用都会挂载同样的模板，一旦栈变深代价就会变得很高。这个示例做了
虚拟化：

```ts
const visible = computed(() => call.index >= call.stackSize - DOM_LIMIT)
```

更早的实例仍然留在 Stack 里——所以关闭顶层后能回落到它们——但在进入最上面 N 个
之前会跳过渲染。当 `DOM_LIMIT = 10` 时，即使嵌套深度到 100，也只会渲染 10 个
对话框。
