## なぜ `upsert` ではなく `update` なのか

`call()` が返す promise は**その Call の識別子**を兼ねています。同じ promise
を `Callable.update(promise, newProps)` に渡せば、同じ開いている Call が新しい
props で再レンダリングされます。

これが [`upsert`](/ja/concepts/upsert-and-update) との違いです。`update` では、
どの開いている Call に送るかを正確に選べます——そしてそれがまだ開いている場合
にのみ更新が反映されます（promise を渡さない場合の唯一のフォールバックは
`Callable.update(props)` で、これは**すべて**の開いているインスタンスへブロー
ドキャストします）。複数の並行した注文が、それぞれ自分の promise で追跡され、
単一のスロットを奪い合うことはありません。

## 使いどころ

- Callable の外部から進捗を発する長時間の処理（WebSocket フレーム、サーバー
  送信イベント、タイマーなど）。
- すでに開いているダイアログ上のライブな「視聴者数」や「在席」インジケーター。
- Call の props がマウントされたまま変化する必要があり、かつ呼び出し側がどの
  Call を対象にするか把握している場合。

## 注意点

- **閉じた Call への更新は何もしません。** ユーザーが早めに閉じた場合、その後の
  `update(promise, …)` は黙って無視されます。ループを止める必要があるなら
  `promise.then(…)` で閉じたことを追跡してください。
