## 一つの Callable、二つの終了経路

`mutationFn?` を「未定義かもしれない」型にすると、トリガーが返すものが変わり
ます。`void` の代わりに、`submit()` は `.orEnd(value)` を持つチェーンオブジェ
クトを返すようになります。この一つのチェーンが両方の呼び出し側をカバーします。

- **ハンドラーなし**（「下書きを破棄」ボタン）→ `submit().orEnd(true)` が
  **フォールバックのレスポンス**を即座に返して Call を閉じます。非同期処理も
  pending もない、ただの確認です。
- **ハンドラーあり**（「投稿を公開」ボタン）→ `.orEnd` は**何もしません**。
  MutationFn が実行され（pending が true になり）、それ自身が `call.end(true)`
  を呼びます。

Callable 自体はどちらの呼び出し側にサービスしているかを分岐しません——
`useMutationFlow` が実行時に `mutationFn` が存在するかどうかで解決します。

ハンドラーが必須なケースについては、失敗時にダイアログが開いたままになり
ユーザーが再試行できる[保存フォーム](/ja/examples/save-form)を参照してくだ
さい。
