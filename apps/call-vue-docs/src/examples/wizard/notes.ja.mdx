## なぜ三つではなく一つの Callable なのか

ステップごとに独立した `.call()` を三回連鎖させる**こともできます**。そう
書けば、命令的なコードとしてはむしろすっきり読めるかもしれません。

```ts
const name = await NameStep.call({})
if (!name) return
const email = await EmailStep.call({ name })
if (!email) return
const plan = await PlanStep.call({ name, email })
```

これは動きます。しかし**戻るボタン**が機能しません。子ステップの内部からの
キャンセルでは前のステップを再度開くことができません——前のステップの promise
はすでに解決済みだからです。戻るナビゲーションを駆動するステートマシンを、
呼び出し側のスコープに自分で持つ必要が出てきます。

内部にステップの状態を持つ単一の Callable であれば、そのステートマシンを
本来あるべき場所(ウィザードの内部)に留めたまま、呼び出し側にはクリーンな
単一 promise のインターフェースを見せられます。代償は Callable 自体が大きく
なることですが、その見返りとして呼び出し側はステップについて一切考える必要
がなくなります。

## この形を選ぶべきとき

- 前後の線形ナビゲーションを持つマルチステップフォーム。
- ユーザーがいつでも `null` で離脱できるオンボーディングフロー。
