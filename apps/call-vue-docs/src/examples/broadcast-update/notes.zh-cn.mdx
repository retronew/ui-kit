## 不带 promise 的 update 会命中所有人

`update` 有两种形式。传入 promise 只针对一个调用；省略它，新的 props 会
**广播给所有打开的调用**：

```ts
Upload.update({ state: 'paused' }) // 一次性作用于所有打开的胶囊
```

这是浅层**合并**，而不是替换——`state` 落到每个调用上，但各自的 `label` 保持不变。
所以一次「连接断开」事件就能暂停三个上传，而调用方根本不用追踪某一个具体的 promise。

## 广播 vs. 定向

这与[实时状态更新](/zh-cn/examples/live-status)正好相反：

- **定向**——`update(promise, props)` 只推送给调用方正在追踪的那一个具体调用。
  适合每个调用有各自独立生命周期的场景。
- **广播**——`update(props)` 推送给所有调用。适合每个打开的调用都应该反映的
  环境状态：网络连接、全局模式、共享时钟等。

## 注意事项

- 合并意味着一次局部广播会保留未涉及的 props——很方便，但要留意某个调用可能
  仍持有一个已经过期的 prop。
