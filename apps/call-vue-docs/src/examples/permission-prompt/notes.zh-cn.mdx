## 不是每个「是/否」都该是布尔值

[确认对话框](/zh-cn/examples/confirm-dialog)返回 `boolean`，对于「继续还是不
继续」这类问题这是对的。但同意授权是另一回事：这个 Callable 返回 `'allow' |
'deny'`。Response 类型本身就是 API 的一部分——一个带命名的联合类型在调用现场
就能自我说明（`result === 'allow'` 比记住 `true` 究竟指向哪一边更直观），也
为未来的扩展留出空间（比如以后加上 `'allow-once'`、`'manage'`），而不必重写
每一处调用方代码。当两个结果不是纯粹的真/假，或者你预期未来会出现第三种结果
时，就应该跳出 `boolean`。

Response 的取值集合也决定了用户能以什么方式离开。这里故意没有背景点击或 Esc
关闭的处理：`'allow' | 'deny'` 里没有「已关闭」这个变体，所以也就故意没有不
作答就关闭提示的方式。对比[列表选择器](/zh-cn/examples/item-picker)，它的
`T | null` Response**确实**对「已关闭」建模，所以它允许点击关闭。你的 Response
类型和你留出的退出方式必须彼此一致。

## 何时使用它

OAuth 风格的授权、权限与 Cookie 提示、「同意这些条款」之类的流程——任何结果
是一个需要存储、记录或据此分支的、带标签的决定，而不是一次性的是非判断的场景。
